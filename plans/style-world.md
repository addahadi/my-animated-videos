# Runtime.tech "World" visual system (plans/style-world.md)

The second Runtime.tech style, added 2026-11-22. It sits next to `plans/style.md` (the "Report" style) and does not replace it. `$video-planner` picks one style per video (field `Style:` in the plan, `style` in the timeline) and `$remotion-builder` loads `src/theme-world.ts`, generated from the token block below. Do not edit this file unless the creator asks to change the World style.

**What World is:** the Report look (light grid canvas, `#EEEEEA` cards with 3 px ink outlines and offset shadows, ink `#0B0F15`, the four Runtime accents, the black caption pill) applied to a new vocabulary: **a top-down map where tokens move and a persistent HUD shows what the system knows**. Only the storytelling device comes from the reference video; the colours and drawing language are Runtime.tech's own.

**Source:** the storytelling devices (moving tokens on a map, persistent meter and slots, zones, close-up cut-aways, top captions with a key-word chip) were analysed from one reference video (91 s, 720 x 1280) on 2026-11-22. The reference's look (night city, glowing streets, navy panels, its buildings and roads) is deliberately **not** used.

**Creator decisions (2026-11-22):**
1. Captions sit at the top as karaoke, in the Report caption pill (ink fill), key word in a yellow chip.
2. Styles may mix: a World video may cut to a Report card for its save frame, and both styles share the same end card.
3. The styles are named **Report** (`plans/style.md`) and **World** (this file).
4. (revision, same day) World keeps the Report colour identity: the light grid background, not a navy one; buildings and roads must not look like the reference.
5. (revision, same day) The all-white map was too pale: blocks now take soft tints of the Runtime accents, grouped in districts, and parks are mint.

## 0. When to use which style

| Use **Report** (`plans/style.md`) when the video is about... | Use **World** (this file) when the video is about... |
|---|---|
| evidence, prices, comparisons, decisions, "what X really is" | a process that moves through space, a system that watches and reacts, flows between many actors |
| things that sit still and get labelled | agents that move and a state that changes |
| e.g. decoy pricing, why an app is free, which phone to buy | e.g. how map apps detect traffic, how recommendation algorithms learn you, how fraud detection flags a card, how a packet crosses the internet, how a hacker moves through a network, game AI |

Rule of thumb: if the clearest explanation is "watch what happens to this little thing as it moves", choose World. If it is "look at this, now look at this label", choose Report. When unsure, the planner proposes one and says why in one line.

## 1. The look in one paragraph

A "paper city" seen from straight above, drawn like a Runtime.tech report: the light grid canvas is the ground and the road surface, roads are marked only by dashed ink centre lines, and every block is a Report card (3 px ink outline, offset shadow) with floor-plan details (inner outline, dashed split, hatched courtyard, small rooftop units). Blocks are coloured by district: each 2 x 2 group of cells takes one soft accent tint (blue, mint, yellow, peach or beige) on about 60 % of its blocks, the rest stay off-white or light grey. Parks are mint cards with outlined trees. Tokens are small flat cards with ink outlines; the viewer is always yellow. A persistent HUD (ink-outlined level pips, round slots that fill) sits under the top caption pill. Close-up beats cut to the plain grid canvas with one card-style object. Flat colour bands (red, green, blue at about 45 % opacity) mark roads or areas; nothing glows.

## 2. Tokens (generate `src/theme-world.ts` from this block)

Shared tokens (`light`, `accent`, `caption`, `shadow`, `stroke`, fonts, `motion.bezier`, `canvas`, `safe`) come from `src/theme.ts` and are referenced, never redefined.

```ts
export const world = {
  map: {
    ground: light.bgCenter,          // roads are the canvas itself
    grid: light.gridMajor, gridStep: 120,   // grid moves with the map
    laneDash: 'rgba(11,15,21,0.32)', // dashed ink centre lines, 3 px, dash 18 / gap 22
    districts: ['#CDD4F2', '#C4E6D3', '#F3E2A8', '#F5D5BE', accent.beige],  // blue, mint, yellow, peach, beige tints
    neutralBlocks: [light.surface, '#E3E5E1'], districtShare: 0.62,  // one tint per 2 x 2 cell district
    blockStroke: light.ink, blockStrokeW: 3, blockRadius: 12,
    blockShadow: 'rgba(11,15,21,0.13)',   // offset (6, 8), like Report cards
    detail: 'rgba(11,15,21,0.22)',        // floor-plan lines, rooftop units
    hatch: 'rgba(11,15,21,0.16)',         // hatched courtyards / plazas
    park: '#B9E0CA', tree: '#86C7A3',     // mint, outlined in ink
    veil: 'rgba(223,225,220,0.65)',       // fades the map under a close-up object
  },
  agent: { hero: accent.yellow, neutral: light.surface, threat: accent.red, system: accent.blue,
           stroke: light.ink, shadow: 'rgba(11,15,21,0.22)' },
  hud: { on: light.ink, off: light.surface, stroke: light.ink, slotDash: 'rgba(11,15,21,0.45)',
         slotQ: light.mono, plate: light.surface, zone: accent.blue, zoneFill: 'rgba(85,107,209,0.12)',
         alert: accent.red },
  caption: { fill: caption.fill, active: caption.active, upcoming: caption.upcoming,
             chip: accent.yellow, chipText: light.ink, radius: 18, height: 88, centerY: 372, size: 62 },
  layout: { headerY: 270, captionY: [328, 416], hudY: 500, slotsY: 600, contentY: [690, 1300], panelObjectY: 900 },
  motion: { camPan: 1.2, camZoom: [0.85, 1.6], tokenSpeed: 260, ping: 0.9 },
};
```

Road colour bands: red (`accent.red`) = jam / danger, green (`accent.green`) = clear / good, blue (`accent.blue`) = the system's route or reach. Opacity about 0.45, width road minus 26 px, round caps, no glow.

## 3. Typography

Same families as Report (section 3 of `plans/style.md`): Tajawal 800 for Arabic, Archivo 800/900 for Latin display, JetBrains Mono for Latin labels.

| Role | Font | Size at 1080 |
|---|---|---|
| Top caption | Tajawal 800 | 62 px (shrinks to fit, min 48) |
| Zone label, slot labels | Tajawal 800 | 28 to 34 px |
| Data tags on the map (`4 KM/H`) | JetBrains Mono 700 caps on an ink pill | 22 px |
| Panel title | Archivo 900 | 140 to 170 px, ink |

## 4. Layout (1080 x 1920)

```
y    0 ┌──────────────────────────────┐
         app UI (keep clear)
y  270   Runtime.tech ········ TOPIC      ← header (body scenes, light mode)
y  328 ┌──────────────────────────────┐
       │  caption pill (karaoke)       │  ← captionY 328–416
y  416 └──────────────────────────────┘
y  500        ▬ ▬ ▬ ▬ ▭                   ← level meter (hudY)
y  600       (◉)(◉)(◌)(◌)                 ← slot tray (slotsY)
y  690 ┌──────────────────────────────┐
       │   tokens / zone / object      │  ← content 690–1300
y 1300 └──────────────────────────────┘
         keep clear (app UI, bottom 450 px)
```

- The **map is full bleed** (it is the background), but tokens, zones and labels that matter stay inside x 165 to 915, y 690 to 1300. The hero token is never under the right-edge button column (x > 940).
- **Header:** the Report `HeaderStrip`, light mode, at y 270. Hook and end card have none.
- **HUD** (meter + slots) is optional per video but, when used, persists across map and panel scenes at the same position. It hides for the save frame.
- **Panels:** the Report `GridCanvas` (light) with one card-style object centred at y about 900. Never more than two objects.
- **End card:** the shared `EndCard` (Report section 6, scene 8).

## 6. Scene recipes and structure

1. **Hook (0 to 5 s).** Map shot, camera already moving, the hero token in trouble or in motion. A meter or a single slot appears in the first second.
2. **Title panel (optional, 1 to 3 s).** Grid canvas with the subject in big display type.
3. **Old way vs new way.** Map shot of the simple version, then the panel where the "new" mechanism is named.
4. **Mechanism on the map.** Tokens act it out; the HUD changes with each spoken idea (a slot fills, the meter moves, a zone appears, a road band appears).
5. **Evidence panel.** `IconDisc` or `EvidenceBoard`: one object per spoken item.
6. **Consequence.** Back to the map: the system reacts (surround, reroute, flag), HUD turns red if it "has you".
7. **Save frame.** A Report card (`MiniUI` or a cheat-sheet `Card`) on the grid canvas, HUD hidden, held at least 2 s.
8. **End card.** The shared `EndCard`.

## 7. Motion

- **Camera on the map:** eased pans and zooms (`EASE_IN_OUT`, about 1.2 s per move, scale 0.85 to 1.6). Rotation only on a cut. **No shake.**
- **Tokens** move along road lanes (right-hand lane = centre line ± 21 px) at a steady speed with eased starts and stops.
- **HUD pops:** slots and pips use `SPRING.pop` (overshoot about 1.08).
- **Cuts:** map to panel is a hard cut on a sentence boundary, or a 0.25 s cross-fade.
- **Road bands** draw along the road over about 1 to 1.4 s (direction follows the story; right to left in Arabic when there is no physical direction).
- Pings are the only looping motion. Everything animates from the frame counter.

## 8. Pace

Same as Report: a new element or state change at least every 3 s on average, never more than 5 s without one.

## 9. Arabic (Darija) adaptation

Same rules as `plans/style.md` section 9: Tajawal, right to left, never letter-spaced; Latin terms isolated with `<bdi>`. HUD rows (meter, slots) fill right to left.

## 10. Look-alike checklist (compare every review still against this)

1. Background is the light grid canvas (as the map ground or a panel). **No dark or navy backgrounds, no night colours, no glows.**
2. Blocks, tokens, slots and pips are Report cards: 3 px ink outline, offset shadow. Blocks use the district tints (soft blue, mint, yellow, peach, beige) mixed with off-white; never saturated fills on blocks, so the hero token and the road bands stay the loudest colours.
3. Roads are the canvas with dashed ink centre lines; no asphalt, no crosswalks, no street lights.
4. The viewer / main subject token is yellow; red = threat or jam, green = clear or good, blue = the system. No other meanings.
5. Header `Runtime.tech` (light mode) in body scenes at y 270; hook and end card have none.
6. The caption pill sits at y 328 to 416, ink fill, at most 5 words, spoken words white, upcoming dim, key word in a yellow chip.
7. HUD (if used) keeps the same position across scenes and hides for the save frame.
8. Important tokens and labels stay inside x 165 to 915, y 690 to 1300.
9. Camera moves are eased; no shake.
10. Every claim is shown as a state change (slot filled, meter moved, zone, road band, stamp), not just text.
11. A change at least every 3 s on average, never a 5 s gap.
12. The save frame is a clean card held at least 2 s; the end card is the shared `EndCard`.
13. Nothing copied from the reference (section 11).

## 11. Copy the system, not the brand

The reference is a GTA 6 video. Do not reuse: its night palette, glowing streets, asphalt roads and crosswalks, its building style, its navy panels, GTA names or logos, the wanted-level star meter, its police car designs, its wording, its comment-poll content or its outro line. A game may be named when the video is about it, following `plans/style.md` section 14 (real logos only as images, never on fakes).
