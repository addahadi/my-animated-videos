## Design plan

- Palette: canvas #F0EFF4, surface #FFFFFF, ink #111214, neutral #D2D4D9, action #0087FA, warning #FFC400. Blue indicates active transfers/selection; yellow indicates a fault or risk. Old/new software versions are written and shaped badges, not color-only states.
- Typeface: locally bundled Tajawal Bold for Arabic and Latin; large numbers use compatible system sans-serif. Heading 64–78px; principal labels 45–52px; small context 32–38px only when nonessential. No bottom narration captions.
- Persistent subject: eight clearly numbered software servers. Server 8 keeps its identity from the first hook to the last lesson. Order tickets carry BUY/SELL names, execution check marks and fault symbols, not meaningless particles.
- Layout: quiet branding at x=90, y=170; topic/date opposite; heading at y=310–430. Narrative stage x=100–930, y=510–1350. No essentials in top 250, bottom 450 or right 150 pixels. Stable camera; object movement explains context changes.
- Hook: a recognizable server sends repeated stock-order tickets toward an exchange while a yellow fault interrupts the route. The headline names the stakes; no fake live dollar counter.
- Explanation: first a readable customer → Knight → exchange relationship, then the same server expands into the fleet. The eighth server's missed update is visible as an unfilled update receipt. A software switch controls paired old/new application panels; do not open hardware interiors.
- Payoff: completed customer order remains beside continued outgoing orders. During the attempted repair, NEW badges physically leave the other servers and old-function indicators appear, so the action visibly causes the escalation. A small engineer at a repair terminal clarifies the human response without blaming a caricatured employee.
- Loss reports: large dated $440M / >$460M treatments tied to announcement versus later findings. No invented financial chart. The final practical checklist uses a gate that actually blocks the faulty order stream.

## Layout comparison and critique before building

Rejected: ten identical rounded information cards, floating server icons, generic counters and isolated fades at each audio boundary. They obscure the missed-deployment mechanism and feel interchangeable with other topics.

Chosen: a physical-looking but schematic server fleet and trading tickets, with asymmetrical software comparison panels and a continuous route. Card surfaces occur only where they represent a real order, software window, dated report or checklist. Use open space rather than filling the stage with UI chrome.
